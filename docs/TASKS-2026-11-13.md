## T1 上下文按宿主实例去重（阻塞级）

### 问题

`PopoverSuggest` 的子类每敲一个键都会调用一次 `open()`：

- 输入框补全：`showSuggestions()` → `updatePosition()` → `this.open()`
- 编辑器补全：`showSuggestions()` → `updatePosition(true)` → `this.open()`

`open()` 在 `isOpen` 时提前返回，但 `HostPatcher` 的包装器在返回后照样执行 `onSurfaceOpen`。`main.ts:119` 的 `contexts.get(context.id)` 用的是自增 id，永远查不到旧上下文。旧上下文仍然 alive（同一容器、同一 values），`pruneDead()` 删不掉。

后果：输入 4 个字符 = 4 个上下文、36 个 keymap handler、4 个 MutationObserver、4 个防抖器。带输入框的 popover 会并发跑 4 次自动匹配，开启自动确认时可能重复提交。

### 实现要求

1. `SuggestionContext` 增加 `readonly host: unknown`，作为构造参数。
2. `SuggestionAttacher` 两个入口传 `host`：`attachSuggestModal` 传 modal 实例，`attachPopoverSuggest` 传 popover 实例。
3. `main.ts` 的 `onSurfaceOpen` 改为接收宿主实例：

```ts
private onSurfaceOpen(host: unknown, attach: () => SuggestionContext | null): void {
  this.pruneDead();
  const live = this.contexts.all().find((c) => c.host === host && c.isAlive());
  if (live) {
    this.contexts.touch(live.id);
    this.refreshBadges(live);
    return;
  }
  // 原逻辑
}
```

4. `HostPatcher.install` 的回调签名改为传 `self`（已经有 `self`，只是 `main.ts` 当时丢了）。

### 验收

- 在 popover 场景连续触发 5 次 `open()`：`contexts.size() === 1`、`shortcuts.count() === 1`。
- 快速切换（每次只 open 一次）行为不变。

## T2 卸载时不得删除后来者的补丁

### 问题

`HostPatcher` 恢复时无条件 `delete target[method]`。若 Quick Select 之类的插件在我们之后加载并包住我们的包装器，我们卸载会把它的那层删掉，它静默失效直到重启。

### 实现要求

1. 包装器内部先判断自身是否仍然有效：

```ts
private active = false;   // install 时 true，uninstall 时 false

const wrapped = function (this: unknown, ...args: unknown[]): unknown {
  const result = fn.apply(this, args);
  if (!self.active) return result;      // 卸载后只做透明转发
  ...
};
```

2. 恢复时先比对当前值：

```ts
this.restorers.push(() => {
  if (target[method] !== wrapped) return;   // 已被别人包住，保留链条
  if (hadOwn) target[method] = original;
  else delete target[method];
});
```

### 验收

- `test/HostPatcher.test.ts` 增加：装我们的补丁 → 模拟第三方再包一层 → `uninstall()` → 第三方包装器仍在，且调用结果正确。

## T3 跨窗口（popout）判断与修饰键状态

### 问题

三处，读码可确认：

1. `SuggestionAttacher.ts:72` 与 `:117` 用 `container instanceof HTMLElement`。popout 是独立 realm，判断恒为 false，整个窗口一个功能都不挂。
2. `ModifierTracker` 只绑主窗口的 `activeDocument`，popout 里的方向键不会被记录。
3. 序号可见性靠 `body.snapto-modifier-down`，class 只加在主窗口 body 上，popout 里永远不显示。

### 实现要求

1. `utils/dom.ts` 新增鸭子类型判断，替换 `instanceof`：

```ts
export function isElementLike(value: unknown): value is HTMLElement {
  return (
    typeof value === "object" &&
    value !== null &&
    (value as Node).nodeType === 1 &&
    typeof (value as HTMLElement).querySelectorAll === "function"
  );
}
```

2. `SuggestionAttacher` 全部改用它。删除没有被调用的 `isElement` 与 `isTextEntryTarget`。

3. `ModifierTracker` 改为多文档：

- 内部维护 `Set<Document>`，同一个 document 只绑一次。
- 新增 `attachDocument(doc: Document)`；`main.onSurfaceOpen` 里调用 `tracker.attachDocument(context.containerEl.ownerDocument)`。
- 每个 document 的 `keydown`/`keyup`/`blur` 各自监听，body class 加在**该 document 自己的 body** 上。
- `stop()` 清理全部监听与 class。
- 方向键回调逻辑不变，仍走 `contexts.active()`。

### 验收

开一个 popout 窗口，在其中打开快速切换：序号在按住修饰键时可见，`Mod+2` 能打开预期笔记。结果写进 `FEATURE_MATRIX.md` 的运行时日志。若不通过，如实记录为「popout 不支持」并在 README 写明。

## T4 两处边角修正

### T4a 场景开关即时生效

`onSettingsChanged` 只重算快捷键，不重算场景开关。关掉某个场景时，已经打开的界面仍然响应数字键。

实现：在 `onSettingsChanged` 中遍历 `contexts.all()`：

```ts
if (this.settings.scenes[context.scene]?.enabled) {
  this.syncContext(context);
  this.refreshBadges(context);
} else {
  this.shortcuts.dispose(context.id);
  this.autoMatch?.unwatch(context.id);
  this.badges.clear(context);
}
```

### T4b click 兜底的索引错位

`SuggestionContext.clickRow(index)` 拿到的是 **values 索引**，却用来取「过滤掉 group 行之后」的数组。有分组行时点击到错误的行。

实现：抽出 `rowForValueIndex(valueIndex: number): HTMLElement | null`，复用 `getCandidates()` 的行/值配对逻辑（`oneRowPerValue ? rows[i] : plainRows[cursor]`），`clickRow` 改用它。

## T6 运行时校验脚本扩展

`scripts/runtime-check.mjs` 现在只在首次打开后断言 `shortcuts.count() === 1`，从不复查。这正是 T1 被漏掉的原因。

追加两项检查：

1. **重复输入**：对同一个 `.prompt-input` 连续 dispatch 3 次 `input`（值递增），等待后断言 `contexts.size() === 1` 且 `shortcuts.count() === 1`。
2. **自动匹配**：查询填入完整标题后等待 `delayMs + 200`，断言 `.suggestion-item.is-selected` 的标题等于预期值。

保持脚本零依赖、退出码可用于 gating。

## 风险

- T3 改动 `ModifierTracker` 的监听结构，涉及多文档生命周期。若 `stop()` 漏掉某个 doc 的监听，会造成跨窗口的残留 class。验收时务必 popout 开关一次后再卸载插件检查。
- T1 去重依赖 `host` 引用相等。若宿主为每次 open 新建实例（目前 `SuggestModal` 与 `PopoverSuggest` 都是单实例复用），判断会失效。实现时在 `attach` 里保留一次 `console.debug` 便于排查，受 `settings.debug` 控制。
